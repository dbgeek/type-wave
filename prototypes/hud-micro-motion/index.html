Micro-motion for the dictation pill

Hold Space (or the button) the way you'd hold fn. All three pills get the same input. Shipped reproduces src/hud.zig exactly: a 20 Hz pump with implicit animations off. A changes only things Core Animation can do natively. B renders A's geometry through an SDF shader, as a stand-in for a Metal pass. The pill is the real 300×22 geometry; use zoom 1× to judge it at true size and slow-mo to inspect it.

Today

Heights and dot bounce are poked at 20 Hz with actions disabled, so they step at 20 fps. The scroll jumps one 10 pt slot at a time. Only the window fade and the bars→dots crossfade are interpolated by Core Animation.

A · Core Animation track

Everything here maps to a stock Core Animation mechanism, listed under each toggle. The pump stays at 20 Hz and CA interpolates in the render server, so there's no new rendering stack. With every toggle off it is identical to Today.

B · Shader track (Metal stand-in)

Uses A's geometry and toggles, but draws every mark as a signed-distance shape in one fragment shader. That makes a gooey smooth-union possible, so bars melt into dots and dots melt into each other. WebGL stands in for Metal; the shader would port to MSL (or a Core Image blur+threshold filter) nearly line for line.

What to lock

  • Smoothness: do the four smoothness toggles ship as a first, low-risk PR? They add no new choreography, just the same marks at display rate.
  • Choreography: which of the waveform and moment toggles ship. Each adds a MarksFx/WindowFx case or a Chrome-only animation. Check that Degraded still reads as an amber pulse (ADR-0004) under converge.
  • Shader track: is the goo worth a rendering pipeline? If yes, try a Core Image blur+threshold filter on the layers before a Metal pass. Glow would amend ADR-0002.
  • Reduce Motion: with it on, unfurl, gather, converge, squash and ripple fall back to Today's fades and crossfade. Is that the right cut?
